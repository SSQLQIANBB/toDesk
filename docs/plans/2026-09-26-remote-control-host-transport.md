# 原生引擎启动与协商边界

当前源码版本为 `0.4.0-beta.1`，构建号 5；初始启动协调层记录为 `0.3.0-beta.1`。对应 `host_transport.rs`、`identity.rs` 与 `host_runtime.rs`。这是产品原生接入的基础层，开发 harness 已复用；尚未接通正式 Socket 被控适配器，不能据此开放远控入口。

## 1. 启动前占用授权

`RuntimeClaim::reserve` 在校验资源和创建子进程之前，独占原生系统确认产生的 `LocalConsent`。网页不能提供该记录，重复启动不能再次使用同一确认。`PreparedHost::bundled` 只从 Tauri 的固定 Resources 加载已验证资源，不接收程序路径、启动参数、动态公钥或测试选项。

启动失败、准备对象被丢弃或连接凭据验证失败会撤销这次占用并回收子进程。清理按原始会话和原生代次匹配；旧启动的迟到清理不能取消停止之后的新操作。资源验证/进程创建结束后再次核对授权，覆盖“启动期间用户停止”的竞争。成功连接时占用只转移给一个 `HostRuntime`，由其现有独立看门狗继续管理。

准备期最多 30 秒，并取本地同意截止的较早值。收到 offer 不重新计时，开始媒体之前始终检查该截止；不能利用候选引擎冷启动较慢延长建连权限。当前开发适配器按原生循环检查准备期，正式适配器仍须拥有独立于 WebView 的调度和停止路径。

## 2. 原生协商证据

offer/answer 的 SDP 各限制为 64 KiB，要求明确的 SHA-256 指纹；重复字段可以表示同一指纹，不允许不同媒体段给出矛盾指纹。原生实际 DTLS 事件只能来自 MAC 校验通过的继承管道，双方指纹必须分别匹配 answer/offer，且同一协商只接受一次。之后服务端签名 connection proof 仍需由 `HostRuntime` 绑定本地同意和实际指纹验证。

未配置时仍只允许 loopback。新版源码增加 `configure_ice`：首次 offer 前验证会话绑定的服务端 ICE 签名，随后经认证管道配置 GStreamer。网络模式允许数值 IPv4/IPv6 的 host/srflx/prflx/relay 及合法 related-address，拒绝主机名、未知类型、非法端口和多行注入；收发方向各最多 128 个候选。收到引擎 `network-configured` 后才接收 answer。已有 UDP/TCP 真实强制中继证据，具体配置、测试边界和现网短期凭据待办见 [TURN 接入说明](../remote-control-turn.md)。此前打包的资源候选仍是回环版本，尚未重新打包。

只识别可靠有序的 `rc-state-v1`、`rc-input-v1` 原生开放事件。开放通知可幂等重复；未知通道拒绝。连接凭据已验证且两个通道均开放后才交付排队字节给运行时。每条消息最多 4 KiB，队列最多 32 条，base64url 必须规范编码。实际输入仍经过现有权限、租约、布局、代次、窗口和独立画面活性检查。

引擎在运行时尚未安装媒体租约时报告 `media-started` 会被拒绝。原生协调层不能用进程 ready、通道 open、信令消息或连接凭据代替媒体租约。

## 3. 排队时间与停止

IPC 解码时记录本机 `Instant`，它不在协议 JSON 中，也不能由子进程或网页提供。该接收时间穿过协商队列传递给运行时：超过 3 秒或来自未来的通道消息拒绝，旧心跳不能在出队时重新获得完整活性期限，真实呈现进度也保留原接收时间。

权限、租约和系统可用性始终以实际处理时刻检查；控制心跳的最新接收时间单独记录。不能把接收时间当成当前时间，否则它早于近期租约/监督更新时会触发错误的时间倒退判断。原生看门狗仍按当前单调时间执行，过期不会因为队列恢复而重新授权。

TURN 续行保留签名封装、DataChannel JSON 和 MAC IPC 线路格式，新增 `ice-config` 签名用途与 `configure-ice` / `network-configured` 消息。公开测试密钥只存在于测试/harness；正式可信公钥和能力门禁仍为空/关闭。

## 4. 验证与后续

默认 Rust 测试 121 项通过，2 项环境依赖测试保持忽略。新增覆盖无同意不启动、并发占用、启动失败、启动期间停止后真实 `/bin/sleep` 子进程被回收、旧清理不取消新操作、固定准备期限、实际指纹匹配、协商重放、候选与通道上限、租约前零媒体、过期队列和带有效租约的旧心跳。

通过共享协商层的系统 WK 实测包含真实采集冻结与包内引擎租约到期。冻结约 3,043ms 暂停、10,080ms 结束；7 秒租约约 7,108ms 停止。两例均取得记录型输入 ACK `[1,2,3]`，授权前零帧，停止后采集和引擎进程退出，未执行 OS 输入或保存画面。

正式产品被控适配器仍须接入设备在线身份、会话绑定信令、原生事件调度、续租 challenge 和托盘停止；随后验证实际系统确认与输入执行器。资源的冷启动、依赖材料、签名、公证和跨平台限制仍见[引擎打包说明](../remote-control-engine-packaging.md)。本轮不自动点击系统授权、不注入 OS 输入、不部署服务端或发布安装包。
